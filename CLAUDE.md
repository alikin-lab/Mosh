# CQ Popup Testing Agent

Агент автоматически тестирует всплывающие окна (попапы) на сайтах, где установлен Carrot Quest.
Обнаруживает два типа багов: наложение попапов и слишком быстрое повторное появление.

## Структура проекта

```
agent/
  config.py          — CSS-селекторы трёх типов попапов, константы
  popup_detector.py  — мониторинг DOM через Playwright (polling каждые 0.5 сек)
  browser_session.py — управление Playwright: запуск, навигация, скролл
  carrotquest_api.py — REST API клиент Carrot Quest (события, карточка пользователя)
  reporter.py        — генерация Markdown- и структурированного отчёта (+маркер происхождения)
  test_runner.py     — прогон ОДНОГО сценария, оркестрация всего вышеперечисленного
  scenario.py        — контракт сценариев (navigate/wait/scroll/exit_intent/click/open_chat)
  run_suite.py       — прогон ВСЕЙ серии одной командой: прогон→валидация→SUMMARY→run_token
  summary.py         — агрегатор отчётов в markdown-таблицу для чата (помечает фабрикации)
  validate.py        — страж целостности: отличает настоящий отчёт раннера от сочинённого агентом
  report_html.py     — HTML-дашборд из валидированных JSON (рендерит код, не агент)
```

## Запуск теста

```bash
# Установить зависимости (один раз)
pip install -r requirements.txt
playwright install chromium

# Запустить тест
python -m agent.test_runner \
  --url https://bitrix.carrotquest.ru \
  --scenario "Ты потенциальный клиент, хочешь купить продукт. Осмотри сайт." \
  --extra-urls https://bitrix.carrotquest.ru/products/ \
  --duration 120 \
  --no-headless
```

## Ключевые параметры

| Параметр | Описание | Дефолт |
|----------|----------|--------|
| `--url` | Стартовый URL | обязателен |
| `--scenario` | Текстовая легенда (для отчёта) | — |
| `--extra-urls` | Дополнительные URL для обхода | [] |
| `--duration` | Длительность сессии (сек) | 120 |
| `--threshold` | Порог быстрого повторения (сек) | 60 |
| `--no-headless` | Показать браузер | выкл |

## Типы попапов и CSS-селекторы

Попапы CQ рендерятся **внутри iframe**, поэтому детектор обходит все фреймы (`page.frames`),
а не только главный. Актуальные селекторы (см. `config.py`):

| Тип | Селектор | Где |
|-----|----------|-----|
| CQ Конструктор | `.popup-block-container` | iframe `carrot-popup-frame` |
| JS Попап | `#popup-card` | кастомный, специфичен для сайта |
| Нотификация / правый виджет | `.cq-wrapper` | iframe `carrot-messenger-tooltip` |

Для разведки селекторов на новом сайте: `--debug` (дампит все popup-like элементы из всех фреймов).

## Типы багов

- **overlap** — два попапа одновременно видимы в DOM
- **rapid_succession** — новый попап появился менее чем через 60 сек после закрытия предыдущего

## Как получить CQ user ID

После загрузки страницы Playwright выполняет:
```js
window.carrotquest?.data?.user?.id
```
Этот ID используется для запросов к API (`/users/{id}/events`).

## Режим сценариев (команда агентов)

Помимо легаси-флагов, `test_runner` умеет исполнять структурированные сценарии:

```bash
python -m agent.test_runner \
  --scenario-file scenarios/client.json \
  --scenario-id linger-landing \
  --json-out reports/linger-landing.json
```

- Контракт сценария — `agent/scenario.py` (действия: navigate, wait, scroll, exit_intent, click, open_chat).
- Пример файла — `scenarios/example.json`.
- `--json-out` пишет структурированный отчёт (для парсинга агентами).

### Прогон всей серии одной командой (рекомендуется для агента)

```bash
python -m agent.run_suite \
  --scenario-file scenarios/<клиент>.json \
  --http-user <ЛОГИН> --http-pass "<ПАРОЛЬ>" \
  --no-headless
```
Прогоняет каждый сценарий → пишет `reports/<host>/<id>.json` → валидирует → собирает
**два формата отчёта** (`SUMMARY.md` для чата + `report.html`-дашборд для браузера) →
печатает `ИТОГ · run_token=...`. Папка по умолчанию — `reports/<host>`. Это единственная
команда, которую запускает агент-тестировщик: её stdout = доказательство реального прогона.

### Отчёт в двух форматах (оба из валидированных JSON, генерирует код)

```bash
python -m agent.report_html reports/<клиент>     # HTML-дашборд (reports/<клиент>/report.html)
python -m agent.summary reports/<клиент>          # markdown-сводка для чата
```
`run_suite` делает оба автоматически. Важно: HTML рендерит **код** из `reports/*.json`
(не агент вручную) — поэтому дашборд физически не может разойтись с данными прогона.
Сочинённые отчёты в дашборд не попадают (выносятся в баннер).

### Сводный отчёт

```bash
python -m agent.summary reports/<клиент> --out reports/<клиент>/SUMMARY.md
```
Агрегирует все `reports/<клиент>/*.json` в таблицу: баги по сценариям, уникальные баги,
отправленные попапы по всем прогонам. Сочинённые отчёты помечает ❌ и выносит баннер.

### Страж целостности (anti-fabrication)

```bash
python -m agent.validate reports/<клиент>      # или путь к одному .json
```
Автономный LLM-тестировщик может СОЧИНИТЬ отчёт, не запустив прогон (наблюдалось 2026-05-30:
`user_id=10001`, поля `status`/`popup_id`, которых нет в схеме). Страж отличает настоящий
вывод раннера от подделки по: маркеру `generated_by="agent.test_runner"`, полноте схемы,
отсутствию чужих полей, формату `user_id` (реальный CQ id — строка из ≥12 цифр), валидности
`started_at`. Вердикты: `VALID` / `NO_USER_ID` (виджет не загрузился, перезапуск) /
`FABRICATED` (выход ≠0). Продакт ОБЯЗАН прогнать стража перед доверием отчётам.

### Два сигнала бага

- **DOM** (`bugs[]`) — наложение/быстрое повторение, реально видимое на экране.
- **CQ API** (`send_bugs[]`) — баги по таймингам ОТПРАВКИ, считаются автоматически
  (`reporter.detect_send_bugs`): `send_concurrent` (2 разных попапа в пределах
  `SEND_CONCURRENT_WINDOW_SEC`=15с) и `send_rapid_resend` (один попап повторно в пределах
  60с). Этот сигнал надёжнее DOM — ловит кейс даже когда визуальное наложение не зафиксировано.
  `popup_sends[]` — сырые тайминги отправок. **Важно:** API отдаёт события под ключом `data`
  (не `events`), `user_id` забирается в конце сессии с ретраями (`get_cq_user_id`).

## Типы багов (итог)
- `overlap` (DOM) — два попапа одновременно видимы на экране
- `rapid_succession` (DOM) — попап появился < 60с после закрытия предыдущего
- `send_concurrent` (API) — два разных попапа отправлены в пределах 15с
- `send_rapid_resend` (API) — один попап отправлен повторно в пределах 60с

## Команда агентов (продакт + тестировщик)

Архитектура «мозги в агентах»: генерация сценариев и ревью — LLM-агенты по плейбукам,
исполнение прогонов и детекция — детерминированный код `agent/`.

- Плейбуки и автономный флоу: `agents/README.md`, `agents/product_agent.md`, `agents/tester_agent.md`
- Обмен через файлы: продакт пишет `scenarios/*.json`, тестировщик — `reports/*.json`

## Добавление новых детекторов (V2+)

1. Создать новый детектор по образцу `popup_detector.py`
2. Подключить в `test_runner.py` рядом с `PopupDetector`
3. Добавить секцию в отчёт в `reporter.py`
