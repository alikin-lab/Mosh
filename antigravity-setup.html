Mosh · CQ Popup QA Agent

Установка агента
в AntiGravity с нуля

Полный путь нового пользователя: от установки IDE до автономного прогона команды агентов.

Что понадобится

  • Google-аккаунт (для AntiGravity)
  • Python 3.10+ и Git
  • CQ-токены клиента (Auth Token + App ID)
  • ~15 минут
1
Установить AntiGravity

AntiGravity — агентная IDE от Google (форк VS Code с Gemini). Скачай и установи под свою ОС, войди через Google-аккаунт.

👉 antigravity.google/download · Windows · macOS · Linux, бесплатно

2
Поставить Python и Git (если ещё нет)

Проверь в терминале — если команды отвечают версией, всё уже есть:

python --version git --version

Если нет: python.org/downloads (отметь «Add to PATH»), git-scm.com/downloads.

3
Склонировать репозиторий

В терминале (или через AntiGravity: Clone Repository) скачай проект:

git clone https://github.com/alikin-lab/Mosh.git cd Mosh
4
Открыть проект в AntiGravity

В AntiGravity: File → Open Folder → выбери папку Mosh. Открой встроенный терминал (Ctrl/Cmd + `) — все команды ниже выполняй в нём.

5
Установить зависимости

Python-пакеты и браузер для Playwright:

pip install -r requirements.txt playwright install chromium
6
Создать файл .env с токенами CQ
⚠️
Токенов нет в репозитории — их нужно создать вручную. Где взять: дашборд Carrot Quest → Настройки → Разработчикам / Интеграции → API. Скопируй Auth Token (вид app.APPID.xxx) и App ID.

Создай файл .env в корне проекта:

CQ_AUTH_TOKEN=app.APPID.ВАШ_ТОКЕН CQ_APP_ID=APPID
🔒
Файл .env в .gitignore — в git не попадёт. Шаблон лежит в .env.example.
7
Настроить двух агентов в AntiGravity

Создай в AntiGravity двух агентов и вставь им системные промпты из репозитория:

  • Агент «Продакт» → содержимое agents/product_agent.md
  • Агент «Тестировщик» → содержимое agents/tester_agent.md

Описание автономного флоу и протокол обмена — в agents/README.md.

⚙️
Названия пунктов меню зависят от версии AntiGravity. Суть: каждому агенту задаётся его инструкция (системный промпт) = текст соответствующего .md.
8
Включить автономный режим

Включи агентам авто-выполнение команд (auto-run / без подтверждения каждого шага). Тогда команда отработает сама — без бесконечных «да».

🤖
Это и есть смысл флоу: человек задаёт вводные один раз, дальше продакт и тестировщик работают автономно.
9
Запустить — дать вводные продакту

Напиши агенту-продакту вводные о клиенте. Например:

Сайт клиента: https://bitrix.carrotquest.ru Воронка: главная → продукты → заявка/демо. Basic Auth: carrotadmin / <пароль> (если сайт под паролем)

Дальше команда сама: продакт спроектирует сценарии → тестировщик прогонит → продакт сверит отчёт → ты получишь сводку.

1.
Продакт пишет scenarios/<клиент>.json
2.
Тестировщик прогоняет каждый сценарий → reports/<id>.json
3.
Продакт ревьюит, при проблемах возвращает на доп. проверку
4.
Сводка: reports/<клиент>/SUMMARY.md со ссылками на карточки
10
Проверка вручную (необязательно)

Чтобы убедиться, что всё работает, прогони всю серию одной командой и проверь целостность:

python -m agent.run_suite --scenario-file scenarios/bitrix.json --no-headless python -m agent.validate reports/bitrix.carrotquest.ru

Сайт под паролем — добавь --http-user ЛОГИН --http-pass "ПАРОЛЬ". В конце run_suite печатает run_token, а validate должен сказать ✅ Все … валидны.

— Если что-то пошло не так —
🕵️
В отчёте user_id: не определён и нет попапов? Скорее всего запуск в headless — CQ-виджет не грузится. Гоняй с --no-headless (в Linux/AntiGravity — под виртуальным дисплеем xvfb).
🔑
Сайт открывается с ошибкой авторизации? Он под HTTP Basic Auth — передай --http-user и --http-pass.
🧩
Попапы не находятся на новом сайте? Запусти с флагом --debug — он выгрузит все popup-подобные элементы из всех фреймов, чтобы найти реальные селекторы.
🤥
Агент рапортует «0 багов», но в отчётах user_id: 10001 и поля вроде status? Это фабрикация — агент сочинил отчёт, не запустив прогон. Прогони python -m agent.validate reports/<host>: настоящий вывод раннера помечается ✅ VALID, выдумка — ❌ FABRICATED. Требуй честный перепрогон через agent.run_suite.
