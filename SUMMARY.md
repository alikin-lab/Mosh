## Контекст и проблема

Команда внедрения Carrot Quest регулярно сталкивается с багами после запуска маркетинговых сценариев на сайтах клиентов. Самые частые — **наложение попапов** (два окна одновременно на экране) и **слишком быстрое повторное появление** попапа. Это портит UX клиентов и подрывает доверие к продукту.

Идея: создать агента, который **автоматически обходит сайт клиента** и выявляет эти баги до того, как их увидит конечный пользователь.

| JS попап | `.cq-popup__body` |
| Нотификация бота | `[data-resize-notification]` |

### Блок 3 — Исследование платформы AntiGravity

Через веб-поиск выяснено: **AntiGravity** — новая IDE от Google (анонс Google I/O 2026), форк VS Code с Gemini 3 внутри. Ключевое открытие: агент имеет доступ к терминалу, файловой системе и браузеру в изолированном Linux-окружении → **Playwright работает нативно**.

### Блок 4 — Уточняющие вопросы (раунд 2)

**Порог "быстрого интервала":** < 60 секунд между попапами = баг  
**Интерфейс V1:** отчёт в чате AntiGravity  
**Состав отчёта:** временна́я метка бага, хронология событий, ссылка на карточку пользователя  
**Стратегия скриншотов:** только при детекции бага (не постоянно) — экономит токены  
**Подход к детекции:** гибридный — DOM-мониторинг (дёшево) + скриншот при баге

### Блок 5 — Написание кода

Создана полная структура Python-пакета:

```
agent/
  config.py          — CSS-селекторы, константы (порог 60 сек, polling 500 мс)
  popup_detector.py  — фоновый мониторинг DOM, детектирует overlap и rapid_succession
  browser_session.py — Playwright: запуск, навигация, скролл, получение CQ user ID
  carrotquest_api.py — REST-клиент: события пользователя, карточка
  reporter.py        — генерация Markdown-отчёта: баги, хронология, ссылка на CQ
  test_runner.py     — точка входа: CLI + оркестрация всех модулей
```

Дополнительные файлы:
- `.gitignore` (токены, кэши не в git)
- `.env.example` (шаблон для коллег)
- `requirements.txt` (playwright, requests, python-dotenv)
- `CLAUDE.md` (документация для AI-агентов)

**Установлены зависимости** локально: `playwright`, `requests`, `python-dotenv`, Chromium.  
**Smoke test пройден:** все модули импортируются без ошибок.

## Итоговая архитектура системы

```
Пользователь в AntiGravity чате
        ↓ (описывает сценарий на русском)
Gemini-агент в AntiGravity
        ↓ (формирует команду)
python -m agent.test_runner --url ... --scenario ... --duration ...
        ↓
BrowserSession (Playwright)
  → Открывает сайт клиента
  → Параллельно: PopupDetector (polling DOM каждые 500 мс)
      → Детектирует [data-resize-popup], .cq-popup__body, [data-resize-notification]
      → При баге: скриншот + запись в bugs[]
  → Извлекает CQ user ID из window.carrotquest.data.user.id
        ↓
CarrotQuestAPI
  → GET /users/{id}/events — события из карточки пользователя
        ↓
reporter.generate_report()
  → Markdown: баги, хронология, ссылка на карточку
        ↓
Отчёт выводится в AntiGravity чат
```

## Технические решения и почему именно так

| Решение | Альтернатива | Почему выбрали |
|---------|-------------|----------------|
| Playwright Python | Selenium, Puppeteer | Async, современный API, работает в AntiGravity Linux env |
| Polling DOM каждые 500 мс | MutationObserver | Проще, надёжнее, легко отлаживать |
| Скриншот только при баге | Постоянные скриншоты | Экономия токенов и дискового места |
| CSS-селекторы по data-атрибутам | XPath, текстовый поиск | Устойчиво к изменениям вёрстки |
| Markdown-отчёт | HTML, PDF | Нативно рендерится в AntiGravity чате |
| .env файл | Передача токенов в аргументах | Безопасность, не попадает в git |
