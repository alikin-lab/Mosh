# Команда агентов — автономный флоу

Два агента работают в связке внутри AntiGravity. Человек задаёт вводные о клиенте
**один раз**, дальше команда тестирует сама.

```
Человек ──(URL + воронка)──▶ ПРОДАКТ
                               │ 1. проектирует сценарии
                               │ 2. пишет scenarios/<клиент>.json
                               ▼
                            ТЕСТИРОВЩИК
                               │ 3. гоняет каждый сценарий через test_runner
                               │ 4. пишет reports/<id>.json + сводку
                               ▼
                            ПРОДАКТ
                               │ 5. ревью отчёта по чек-листу
                               │    ├─ есть проблемы → вернуть тестировщику доп. проверку
                               │    └─ всё чисто → финальный отчёт человеку
                               ▼
                            Человек получает результат
```

## Протокол обмена (через файлы)

- **Продакт → Тестировщик:** `scenarios/<клиент>.json` (формат — `agent/scenario.py`)
- **Тестировщик → Продакт:** `reports/<scenario_id>.json` по одному на сценарий
- **Доп. проверка:** продакт называет конкретные `scenario_id`, тестировщик перезапускает их

Файловый протокол делает флоу устойчивым: агенты не зависят от «живого» диалога,
любой шаг можно перезапустить.

## Настройка в AntiGravity

1. Создай двух агентов и вставь системные промпты:
   - Продакт → [`product_agent.md`](product_agent.md)
   - Тестировщик → [`tester_agent.md`](tester_agent.md)
2. **Включи автономный режим** (auto-run / без подтверждения каждой команды), чтобы
   агенты выполняли команды терминала и Playwright-прогоны без ручных «да». Это и есть
   требование «флоу сужается до вводных о клиенте».
3. Убедись, что в проекте есть `.env` с `CQ_AUTH_TOKEN` и `CQ_APP_ID`, установлены
   зависимости (`pip install -r requirements.txt`, `playwright install chromium`).

## Почему «мозги в агентах», а не в коде

Генерация сценариев и ревью отчёта — это **суждение**: их делают LLM-агенты по плейбукам.
Исполнение прогонов и детекция багов — **детерминированный код** (`agent/`), который
агенты просто вызывают как инструмент. Так творческая часть гибкая, а измерения —
воспроизводимые.
